# k8s-cluster-provisioning — Documentation

## Short purpose

This repository contains Terraform code and helper scripts to provision a small Kubernetes cluster (master + workers) and bootstrap nodes with Ansible. The repo is organized into a root Terraform configuration and two reusable modules (`network` and `vm`). A helper `setup.sh` script automates Terraform runs and prepares an Ansible inventory.

Repository layout (important files)

- `main.tf` — root Terraform configuration that wires modules and resources.
- `provider.tf` — Terraform provider(s) configuration (cloud provider and authentication).
- `variables.tf` — root variables and defaults used by the configuration.
- `terraform.tfvars` — project-specific variable values (sensitive values may live here).
- `locals.tf` — local values used by Terraform (e.g., node sizes). Example excerpt:
  ```hcl
  locals {
    nodes = {
      master  = "Standard_B2s"
      worker1 = "Standard_B1s"
      worker2 = "Standard_B1s"
    }
  }
  ```
- `outputs.tf` — outputs exposed by the root module, e.g. `master_public_ip`, `worker_public_ips`, `admin_username`, `ssh_key_path`.
- `setup.sh` — helper shell script that runs Terraform, installs `jq` (if needed), extracts outputs and writes an Ansible-style `hosts` inventory, creates `ansible.cfg` and `group_vars/all.yml`, and runs `ansible-playbook`.
- `ansible-playbook.yaml` — Ansible playbook used to install Kubernetes components (present in the repo; ensure it matches your desired tasks).
- `modules/network/` — Terraform module that sets up the network (VNet, subnets, NSGs, public IPs, etc.). See module folder README for details.
- `modules/vm/` — Terraform module that provisions virtual machines and attaches network resources.

## Prerequisites

- Terraform (match the version required by this repo). Install and add to PATH.
- jq (JSON processor) used by `setup.sh` when parsing `terraform output -json`.
- Ansible (control machine that will run playbooks).
- A Bash-compatible shell on Windows: WSL (recommended) or Git Bash. `setup.sh` is a Bash script.
- SSH private key accessible to Ansible and referenced by Terraform/outputs.

Important environment notes for Windows users

- The repo assumes a Unix-like shell for `setup.sh`. On Windows run it via WSL or Git Bash. Example from PowerShell:
  ```powershell
  wsl bash ./setup.sh
  ```
- Alternatively open a Git Bash or WSL terminal in the repo folder and run `./setup.sh`.

## Security notes

- Do not commit private keys or secrets to the repository. Keep them outside the repo and reference via variables or environment.
- `setup.sh` may append host keys to `~/.ssh/known_hosts` — validate hosts separately if in a sensitive environment.
- `ansible.cfg` and `group_vars/all.yml` generated by the script include the private key path; ensure file permissions are restricted.

## Terraform variables (source: `variables.tf`)

This project defines the following Terraform input variables (see `variables.tf`). You can set them in a `terraform.tfvars` file or pass them on the CLI / environment.

- `subscription_id` (string) — Azure subscription ID (required for Azure provider).
- `tenant_id` (string) — Azure tenant ID (required for Azure provider).
- `client_id` (string) — Service principal client ID.
- `client_secret` (string) — Service principal client secret.
- `prefix` (string) — Resource name prefix. Default: `k8s`.
- `location` (string) — Azure region. Default: `eastus`.
- `resource_group_name` (string) — Resource group name. Default: `k8s-rg`.
- `address_space` (list(string)) — VNet CIDR(s). Default: `["10.1.0.0/16"]`.
- `subnet_names` (list(string)) — Subnet names. Default: `["k8s-subnet"]`.
- `address_prefixes` (list(string)) — Subnet CIDR(s). Default: `["10.1.1.0/24"]`.
- `allocation_method` (string) — Public IP allocation method. Default: `Static`.
- `private_ip_address_allocation` (string) — Private IP allocation. Default: `Dynamic`.
- `delete_os_disk` (bool) — Whether to delete OS disk on VM deletion. Default: `true`.
- `delete_data_disks` (bool) — Whether to delete data disks on VM deletion. Default: `true`.
- `vm_size` (string) — VM size. Default: `Standard_DS1_v2`.
- `publisher` (string) — VM image publisher. Default: `Canonical`.
- `offer` (string) — VM image offer. Default: `UbuntuServer`.
- `sku` (string) — VM image SKU. Default: `18.04-LTS`.
- `image_version` (string) — VM image version. Default: `latest`.
- `caching` (string) — OS disk caching. Default: `ReadWrite`.
- `create_option` (string) — OS disk create option. Default: `FromImage`.
- `managed_disk_type` (string) — Managed disk type. Default: `Standard_LRS`.
- `admin_username` (string) — Admin username for VMs. Default: `azureuser`.
- `ssh_key_path` (string) — Path to SSH public key. Default: `~/.ssh/id_rsa.pub`.

## Example `terraform.tfvars`

Create a `terraform.tfvars` file in the repo root with your own values. Do NOT commit secrets like `client_secret` to git.

```hcl
subscription_id = "<YOUR_SUBSCRIPTION_ID>"
tenant_id       = "<YOUR_TENANT_ID>"
client_id       = "<YOUR_CLIENT_ID>"
client_secret   = "<YOUR_CLIENT_SECRET>" # prefer environment or secret store

prefix          = "myk8s"
location        = "eastus"
resource_group_name = "myk8s-rg"

address_space   = ["10.2.0.0/16"]
subnet_names    = ["k8s-subnet"]
address_prefixes = ["10.2.1.0/24"]

allocation_method = "Static"
private_ip_address_allocation = "Dynamic"

delete_os_disk  = true
delete_data_disks = true

vm_size         = "Standard_DS1_v2"
publisher       = "Canonical"
offer           = "UbuntuServer"
sku             = "18.04-LTS"
image_version   = "latest"
caching         = "ReadWrite"
create_option   = "FromImage"
managed_disk_type = "Standard_LRS"

admin_username  = "azureuser"
ssh_key_path    = "~/.ssh/id_rsa.pub"
```

Notes:

- For `client_secret`, prefer using an environment variable or Terraform Cloud/Backend secret, not plaintext in `terraform.tfvars`.
- `ssh_key_path` must point to a public key file accessible from the machine running Terraform.

## `setup.sh` details and runtime behavior

`setup.sh` is a convenience wrapper that:

- Validates that the environment variable `SUDO_PASS` is set (script currently uses it to run `apt-get` non-interactively when installing `jq`).
  - If you don't want to use `SUDO_PASS`, install `jq` manually in your WSL/Git Bash environment before running.
- Runs `terraform init`, `terraform plan` and `terraform apply -auto-approve` in the repo root.
- Extracts Terraform outputs expected by the repo (example names):
  - `master_public_ip`
  - `worker_public_ips`
  - `admin_username` (mapped to Ansible user)
  - `ssh_key_path` (used in generated `ansible.cfg`)
- Installs `jq` via `apt-get` if needed (requires sudo access on the machine running the script).
- Generates these files:
  - `hosts` — Ansible inventory with `[master]` and `[worker]` groups.
  - `ansible.cfg` — with `remote_user`, `private_key_file` and `host_key_checking = False`.
  - `group_vars/all.yml` — with `ansible_user` and `ansible_ssh_private_key_file`.
- Scans remote SSH host keys and appends them to `~/.ssh/known_hosts` to avoid interactive SSH prompts.
- Runs `ansible-playbook ansible-playbook.yaml` using the generated inventory and config.

How to run safely:

1. Prefer running the script from WSL or a Linux shell where `sudo` is available.
2. Install `jq` yourself if you don't want the script to call `apt-get`.
3. Example (WSL):

```bash
export SUDO_PASS="<your-sudo-password>" # optional if you want script to install jq
./setup.sh
```

Or run Terraform and Ansible manually if you prefer explicit control:

```bash
terraform init
terraform plan -out=tfplan
terraform apply -auto-approve tfplan

# inspect outputs
terraform output --json

# then run Ansible manually
ansible-playbook -i hosts ansible-playbook.yaml -u <admin_user> --private-key /path/to/id_rsa
```

## Next improvements (roadmap)

Short-term improvements you can implement quickly:

- Remove `SUDO_PASS` requirement from `setup.sh` and instead check for `jq` and instruct the user to install it manually.
- Make `setup.sh` idempotent and add stricter error handling: `set -euo pipefail`, validate Terraform outputs, write files atomically (tmp -> mv).
- Avoid `terraform output -raw` compatibility issues by using `terraform output -json` and parsing with `jq` (robust across TF versions).
- Move secrets out of `terraform.tfvars` to environment variables, use Terraform Cloud variables, or integrate with a secret manager (Azure Key Vault, AWS Secrets Manager, HashiCorp Vault).

- Add support for other cloud providers (AWS, GCP) by refactoring modules into provider-agnostic interfaces and separate provider modules.

Security & reliability improvements:

- Use managed identities (Azure) or instance profiles (AWS) instead of embedding service principal secrets.
- Use TLS for API endpoints, secure storage for kubeconfig, and restrict SSH access via NSG/security groups.
- Add integration tests and a CI pipeline that runs `terraform fmt`, `terraform validate`, and `terraform plan -out=tfplan` in a safe environment.
